# 深度检测与长期运行优化报告

日期：2026-09-08。范围：当前 LD 源码、配置、数据层、PLC 业务链路和 SunnyUI 界面。用户产量约 2,000 条/天，五年按 3,654,000 条留余量验证。

## 结论和边界

代码级优化及离线验证已进行；不能据此承诺实际 7×24 零故障或五年绝不丢数据。主库不自动删除历史记录。五年保留还依赖可靠磁盘、UPS、独立备份、恢复演练和持续运维。

本次没有启动 PLC 模拟服务器，没有连接/写入实际 PLC，也没有删除或改写现场数据库。测试客户端只存在于单元测试中，不监听端口。所有容量和备份测试在 GUID 临时目录进行。

## 主要问题及修复

| 风险 | 修复 |
|---|---|
| 旧 SQLite 3.46.1 WAL 并发数据库损坏风险 | 换用 System.Data.SQLite 2.0.4 + 原生 SQLite 3.53.3；固定 Windows x64；自动测试断言真实引擎版本 |
| NORMAL 同步不能提供相同的掉电提交保障 | 改用 WAL/FULL；依然需要磁盘遵守同步写入及 UPS |
| Timer 回调堆积、关闭与重连时锁反转 | SerialTimer 不重入、不堆积，释放等待进行中的回调；状态锁与执行锁分离 |
| 失败读取保留旧工号或跨周期拼接 | 同周期不可变快照、有效期、失败字段失效、标志二次读取校验；重连作废整个周期 |
| 入库成功后 PLC 应答失败，重启可能发新批号 | 数据记录和待应答表同事务提交；重启续发原批次/上传成功应答，避免覆盖原测量值 |
| 数据库 SELECT 1 误报正常 | 检查磁盘余量、主库存在及真实 UPDATE 提交；异常停发心跳并显示状态 |
| 全量查询/导出阻塞 UI、长期内存增长 | 后台分页 500 条；CSV 每 1,000 行键集读取；限制刷新并发；退出取消导出 |
| 日志持续占满磁盘 | 汇总 app.log 按大小滚动，30 个 20 MB 副本（另加当前文件）；旧版历史日志不自动清理 |
| 绘制和产品图资源泄漏 | 复用字体、缓存图片路径/修改时间、释放旧图片及关闭定时器 |
| 弹窗、表格和图片风格不统一 | 主界面/退出/指导书同一 SunnyUI 深色主题；清晰文字、完整图片、响应式布局 |
| 产品下拉列表打开时为空/刷新太晚 | 展开前刷新 DataSource，验证弹出列表包含新产品 |

官方依据：[SQLite WAL-reset 缺陷说明](https://www.sqlite.org/wal.html)、[SQLite 发布修复记录](https://www.sqlite.org/changes.html)、[同步等级说明](https://www.sqlite.org/pragma.html#pragma_synchronous)、[在线备份接口](https://www.sqlite.org/backup.html)。该并发缺陷影响旧版 WAL 的多连接并发写入/检查点情形，本项目确有多连接使用，因此不是仅更新版本号。

## 已完成验证

- Release 构建：0 警告、0 错误；Debug 在独立临时输出目录构建通过。原 Debug 目录被用户正在运行的程序占用，没有强制终止该程序。
- 50/50 自动测试通过，包括编码、员工号 600249、重复批次、业务校验、过期快照、读取失败、重连中断周期、串行回调、持久化待应答恢复、未确认通道禁止覆盖、真实 SQLite 备份还原、并发读写与在线备份后完整性检查。
- UI 离屏绘制/边界检查：1280×720、1600×900、1920×1080（当前 100% 缩放）。主窗体、退出确认和全屏指导书已检查；图片四边完整可见；无匹配产品不加载其他指导书。小屏有意使用表格水平滚动，不缩小文字挤入屏幕。
- 下拉弹出列表验证：ALL、DH280GM、NEW-PRODUCT 全部可见；现场库只读检查发现产品 DH280GM。
- 百万条初始基线（索引上界优化前）：SQLite 3.53.3；临时库 147,451,904 字节；首屏 17 ms、筛选页 4 ms；全量读取遍历 69,078 ms；备份及 quick_check 1,096 ms；峰值工作集 41,443,328 字节。
- 上述批量造数使用单 SQL 事务，不是模拟真实每条 FULL 提交吞吐；流式遍历不是完整 CSV 文件写盘速度；结果与机器、缓存、负载相关。

## 五年容量验证

全量导出初测发现仅元组游标不足以约束日期索引范围，365 万条遍历数分钟仍未完成；终止了该临时测试进程（未停止用户程序），将日期标量上界同步推进后复测：

| 项目 | 365.4 万条实测 |
|---|---:|
| 单 SQL 事务造数 | 18,002 ms |
| 首屏 500 条 | 13 ms |
| 产品筛选 500 条 | 4 ms |
| 全量流式遍历（校验数量及严格顺序） | 30,011 ms |
| 主库大小 | 543,109,120 字节，约 518 MiB |
| 在线完整备份 + quick_check | 7,096 ms |
| 测试进程峰值工作集 | 42,422,272 字节，约 40.5 MiB |
| 还原副本记录数 | 3,654,000，通过 |

临时测试数据的产品名为 PRODUCT-0～19，各测量值为固定样本；图片未存入数据库。实际字符长度、索引变更、空页及业务数据分布会改变容量，不应直接当作硬性上限。主库+七个完整日备份按八份估算约 4.35 GB（十进制），再加 WAL、生成中备份、日志、导出和增长余量。建议至少预留 20 GB 专用空间，图片和异机备份另计，按实际增长监控调整。

默认 24 小时备份、自动副本轮换 7 天；这不改变主库历史保留期。若硬盘整体失效而只保留每日异机备份，可能丢失上次异机备份之后的数据；更小恢复点目标需缩短备份间隔及安排外部复制。

## 必须完成的现场验收

1. 在正常停机窗口部署完整新版目录，保存原 DB/配置/旧程序；先对备份副本演练升级和还原。
2. 核验 D4030=600249、D4002/D6000、三个批次号 STRING 与 yyDDD 日期、真实 PLC 字序及地址偏移；执行成功、NG、错误产品、重复上传及跨天场景。
3. PLC 必须先准备数据后置 1，保持数据到 2/3；新请求前保证上位机能看到非 1。现有协议无唯一请求序号，响应丢失与瞬时断电的物理恰好一次不能只靠上位机证明，需与 PLC 程序协同。
4. 受控断网、PLC 重启、写入中断、应答中断、磁盘余量不足测试。禁止直接在生产数据库实施损坏实验。
5. 工控机 168 小时连续实测：核对 PLC 与数据库数量，记录 CPU/内存/句柄、最大响应延迟、异常日志与备份结果；125%/150% 缩放和目标屏幕人工复核。
6. 每月从独立设备上的备份还原，检查行数、日期范围、完整性、随机测量值。禁止多个会话/机器同时对同一 PLC 发批次。
