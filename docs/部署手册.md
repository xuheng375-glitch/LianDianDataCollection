# 联电数据收集部署手册

更新：2026-09-08。适用 Windows 10/11 x64、.NET Framework 4.7.2；默认 100% 缩放，推荐 1920×1080，最低 1280×720。125%/150% 缩放须现场复核。

## 发布与升级

1. 构建：`dotnet build LianDianDataCollection.slnx -c Release`。
2. 将 `src/LianDian.UI/bin/Release/net472` 的程序和依赖整体部署；必须包含 `System.Data.SQLite.dll` 和 **`e_sqlite3.dll`**。本版固定 x64，不能运行在 32 位 Windows。不能只复制 EXE。
3. 升级前停止采集，在旧程序正常退出后备份完整数据库目录、配置和旧程序。优先使用已验证的在线备份副本。旧 WAL/SHM 未确认清空时不得丢弃或单独复制主 DB。
4. 新程序部署到新目录，保留现场 `config/app.ini`；建议 `FilePath` 指向固定绝对路径，避免 Debug/Release/不同安装目录分别建空库。
5. 先在**备份副本**验证打开、行数、日期范围和 `PRAGMA integrity_check`，再安排停机切换。首次启动会添加必要表/索引，不删除历史记录；五年大库初建索引可能耗时。
6. 启动日志记录实际数据库绝对路径和 SQLite 版本，必须为本次验证的 3.53.3。不要把旧版 SQLite DLL 混入新目录。
7. GitHub 只保存源码、测试和文档；现场 ProductPIC、Instruction、Data、Logs 不上传，需独立部署和备份。

## 配置

运行时读取 **EXE 所在目录/config/app.ini**，修改后重启。相对数据库/备份路径以 EXE 目录为基准。推荐固定数据盘绝对路径，不要使用网络共享路径存放 WAL 主库。

```ini
[PLC]
Ip=127.0.0.1
Port=502
SlaveId=1
ReadIntervalMs=200
TimeOutMs=1000
ReconnectIntervalMs=3000
WriteRetryCount=3
WriteRetryDelayMs=200
WordOrder=true
ModbusOffset=1
StringEncoding=UTF8
StringLowByteFirst=true
BatchStringRegisters=3
DateStringRegisters=3
QrGradeStringRegisters=1
SnapshotMaxAgeMs=3000

[Database]
FilePath=Data\lian_dian.db
TestIntervalSec=5
BackupDirectory=Data\Backups
BackupIntervalHours=24
BackupRetentionDays=7
MinimumFreeSpaceMb=1024

[Path]
ProductPicDir=ProductPIC
InstructionDir=Instruction
LogDir=Logs

[Business]
BatchResetTime=00:00:00
HeartbeatIntervalMs=500
PollIntervalMs=300
```

127.0.0.1 是当前本机 AutoShop 配置；现场真机须替换实际 IP。D4030 读取完整 DINT（D4030+D4031）；D4000 只写 0/1；D4002 为 1 时读 D6000 的 A～F。地址详见 PLC 点位表，禁止未经实测改变偏移或字序。

## 五年保存与备份

- 每日约 2,000 条，五年按 3,654,000 条验证。主库不执行自动历史删除；备份也不是按天拆分数据，而是完整主库副本。
- 每次启动后约 60 秒检查备份，成功后按 24 小时间隔备份；程序持续运行才会执行。自动备份写临时文件、在线复制、quick_check 通过后才形成正式 DB。
- 默认仅轮换超过 7 天且符合本服务文件名规则的自动备份，不清理主库或人工备份。重启频繁可能一天生成多个副本，应监控备份目录容量。
- 默认同盘备份只能防误操作，**不能防硬盘损坏**。每天将验证后的完整备份复制至独立磁盘/NAS（NAS 只存备份，不存活动 WAL 主库），至少保留周/月恢复点；每月在另一目录或机器演练恢复。
- 全盘断电/磁盘故障不能靠软件承诺不丢数据：配置 UPS、可靠 SSD、磁盘告警，禁止系统休眠，安排受控更新重启。
- 至少预留 20 GB 专用数据/备份空间，并按监测增长调整；导出文件、图片、外部备份另计。具体测量见深度检测报告。
- 数据库健康检查验证真实提交和磁盘余量。低于 MinimumFreeSpaceMb 或写入失败时健康灯灭并停发心跳，现场必须处理报警。

## 操作及异常处理

PLC/数据库指示灯不闪烁，连接/可写时亮。主窗体、指导书和退出确认统一深色主题。指导书按当前 PLC 产品名称匹配，缺失时不借用其他产品图片；支持全屏、适配、缩放和平移。

产品下拉每次打开前刷新数据库列表，可输入模糊查询。表格每页最多 500 行；小屏通过横向滚动查看后续列。CSV 按查询条件流式导出全部记录，不受页数限制。用 Excel 导入时将批次号列指定为文本保留 00001，超过 Excel 单工作表行数上限的数据请按日期分段导出。导出期间上传测试值可能更新，所以 CSV 不是同一时刻的事务快照；审计用途应从静止备份导出。

退出会停止采集并等待进行中的回调释放，请等待正常退出，不要直接强杀。程序是桌面应用，不是 Windows 服务；可由现场管理员配置登录后计划任务启动。本版只防止同一 Windows 会话重复启动；同一 PLC 禁止跨会话/跨机器运行多个采集实例。

现场验收：先数据、后标志 1，PLC 保持负载至 2/3 应答；每次新请求之间必须让上位机观察到非 1。现有握手无唯一请求序号，必须测试“写应答成功但连接断开/断电”的边界，不宣称跨设备恰好一次。上线前完成断线、掉电恢复、日期跨天、批次上限及连续 168 小时跑批。
