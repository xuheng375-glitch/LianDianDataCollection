## 实施约定

- D4000、D4100、D5700 不进入轮询读取。
- 批次号在线路上保留前导零；数据库现有整数批次号可继续使用，读写边界进行转换。
- 保留现有编码和字节序配置。五位 ASCII 数字在每寄存器两字符的布局下需要 3 个寄存器（5 字节内容加 1 字节 NUL），实际分配长度仍需与 PLC 确认。
- DINT 轮询按新点位分别读取，D4030 员工工号读取两个寄存器，按 WordOrder 组合为完整 DINT，界面和入库均不截取低 WORD。
- 五位批次号的上限为 99999，禁止静默截断溢出的批次号。
- AutoShop 已只读核对：协议地址 4002 的 DINT 为 1，协议地址 6000 为字符 A。按用户要求设置 `ModbusOffset=1`，统一读写换算为 D 号对应同号协议地址；保留公式 `D - 1 + ModbusOffset`，不再额外增减地址。

## 配置与现场验证

- 点位常量：`src/LianDian.Comm/RegisterMap.cs`；运行参数：`config/app.ini` 的 `[PLC]` 节。
- `BatchStringRegisters=3`、`DateStringRegisters=3`、`QrGradeStringRegisters=1`。默认低字节优先、无长度头、NUL 结束；字节序由 `StringLowByteFirst` 控制。若 PLC 使用长度头，需要测试确认后修改编解码，不能只调整长度。
- 现场先验证 D4002＝1 在二维码字段为空时仍正常下发；再设置 D4400=`00001`、D6100=`26188`、D6000=`A`、D6200 为对应产品名称、D4004＝1，确认对应行等级刷新、D4004 回复 2。
- D6100 必须携带目标批次的日期，不能以跨天后的上传当天日期替代。请求期间 PLC 应保持日期、批次号、等级不变，等待应答后再置 0 并发起下一笔。
- 未找到批次、格式错误或已有不同等级时保持 1 并提示；相同等级重传幂等回复 2。二维码更新与待应答记录在同一事务提交，通信中断后可重试。
- 批次数据写入和入库成功后，D4002 写回 2；心跳 D4000 始终仅写 0/1。
